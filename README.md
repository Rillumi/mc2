# ModPilot

Minecraft 模组整理工具：扫描本地模组，识别来源，检查前置和更新，最后导出整合包。

核心闭环：**收集/导入 → 认识 → 整理/比较 → 适配 → 导出**。新功能只有服务这五步之一才会加。

## 提交与同步

- `上传全部.bat`：测试通过后提交当前改动，快进更新 main，同步 Gitee 和 GitHub。
- `上传版本.bat`：同样流程，只同步 Gitee。
- `上传GitHub.bat`：同样流程，只同步 GitHub。
- 无新改动时仍推送已有提交，方便网络失败后重试；两个平台分别核对提交号，某个平台失败不会阻止另一个平台同步。
- 从开发分支运行时，仅支持快进合入 main；发现分叉时停止对应操作，绝不强推。

无需交互的双平台同步：

```bash
node scripts/publish.cjs --message "修复说明"
```

## 能做什么

- 扫描文件夹或直接拖入 `.jar` / `.zip` / `.mrpack`，读出模组名、版本、加载器、作者
- Modrinth 批量哈希识别、项目资料预取与带确认条件的搜索；CurseForge 已有指纹查询，主要用于导出映射，通用依赖检查尚未接齐
- 查缺前置、版本是否满足、重复 ID 和明确互斥声明（只做元数据能看出来的部分）
- 检查更新，区分「有新版 / 已是最新 / 本地更高 / 版本号无法可靠比较」
- 导出 `.mrpack`、CurseForge 整合包、离线 zip、下载清单，生成后自动回读校验
- 图标本地缓存、中文名库、爱发电作者映射（这些依赖后端，见下）

## 快速开始

需要 Node.js 20+。

```bash
npm install
npm start          # 默认 http://127.0.0.1:8737，端口被占会自动往后换
```

Windows 也可以直接双击 `启动.bat`（会用 Edge 打开后台页面）。

不装 MySQL 也能用：扫描、整理、打包、图标全部是前端逻辑，能跑。只是后台的映射表、爱发电、中文名库接口会返回 503。

### 可选：接上 MySQL

首次启动会在项目根目录生成 `db.config.json`：

```json
{
  "host": "127.0.0.1",
  "port": 3306,
  "user": "root",
  "password": "",
  "database": "modpilot"
}
```

填好账号密码后重启，服务端会自动建库建表。数据库只存链接库和作者映射，不存你的模组文件。

### 可选：CurseForge 指纹查询

在「设置」里填 CurseForge API Key（[申请地址](https://console.curseforge.com/#/api-keys)）。不填也能用 Modrinth 那条链路，只是 CurseForge 独占模组识别不出来。

## 如何理解检查结果

- **明确错误（当前程序标签）**：必需前置缺失、版本不符、重复 ID 或适用的禁止共存声明等会进入错误结果并阻止生成整合包；其中平台环境未列出、精确发布 ID 差异仍有判级过重的情况，见下文。下载清单仍可用于排查。
- **警告**：Fabric `conflicts`、NeoForge `discouraged` 等建议避免共存的声明，保留原因，允许生成整合包。
- **待确认**：未知版本、不支持的范围语法、未选定目标端、平台查询失败 / 未识别、平台与 JAR 范围矛盾、原包在线文件尚未展开等，不当作全部通过。
- 打包区、预览和诊断报告列出检查依据与覆盖数量。文件和清单回读成功只表示内容校验通过，不等同于游戏兼容性通过。

当前仍有需修正的判级：平台 MC / 加载器标注不符、同项目精确依赖发布 ID 不一致，可能直接成为阻止打包的 error，尚未普遍经过内部声明复核。文件名兜底推测也未完整记录可信度。详见 [现有逻辑与已知缺口](FUNCTIONAL_LOGIC.md#9-已知缺口与优先修正项)，不能把准备改进的规则当作已经实现。

部分平台互斥命中、JAR 内部禁止范围未命中时，当前程序会保留两份依据并降为待确认。这不证明内部明确声明兼容，该局部处理仍需重审；不能概括成所有来源不同就降低已经命中的内部强互斥。

互斥检查支持 Fabric `breaks` / `conflicts` 和 NeoForge `incompatible` / `discouraged`，会保留声明来源、内部 ID、版本范围及适用端。只匹配最终选择的文件；不凭名字推断互斥对象，不自动删文件。Fabric 常见版本表达式和纯数字 Maven 区间可判定；复杂 Maven 限定符等无法可靠比较的内容列为待确认。

Modrinth 的互斥关系只用于已由文件哈希核对的具体发布文件；项目级与精确版本级要求分开处理。可点「重新查询平台声明与依赖链」刷新。CurseForge 依赖与内嵌 JAR 完整检查仍在待办中。

### 原包在线文件的快速检查

- 导入原包后，使用 SHA-1（仅有 SHA-512 时使用 SHA-512）批量定位精确发布版本，核对文件哈希及已有版本 ID 提示；不凭文件名或 URL 猜身份。原包版本和原始清单保持不变。
- 检查当前方案各版本的 required / optional / incompatible / embedded 关系，覆盖多级前置、共享前置与循环。原包资源文件、实际选中的本地模组和加入方案的在线文件也作为准确身份的提供者核对。
- 指定精确版本时核对该版本；只指定项目时核对存在性，内部版本范围保留待确认。同一文件对应多个发布版本时也保留身份歧义，不重复添加一份。
- 明确缺失时先显示候选，点「加入此候选」后继续检查它的前置；不会自动升级原包，也不会另加其他版本掩盖已有版本不符。可选缺失不报必需项缺失，开启可选项后可查看候选；embedded 先列待核实。
- 尚有未识别文件、上层文件可选或目标端未确定时，不武断认定缺失。原包 JAR 内部 ID、版本区间、内嵌内容仍属深度检查范围；缺失的资源包前置若无法作为 JAR 候选加入，须手动补充资源文件。
- 自动检查和导出前核对都使用当前方案；候选加入 / 移除会重新检查。网络失败、超限可手动刷新，过期请求不会写回当前方案。快速检查只查元数据，不下载、安装或运行 JAR。
- 边界：最多 1,024 个文件、8,192 条关系、100 次接口逻辑调用、90 秒等待预算；哈希每批 80 个，单次请求 15 秒超时并最多尝试 3 次。项目候选列表超过 500 项时不静默截取。超限显示未完成，已发出的底层请求按自身超时结束。

## 导出完整性

- 补充的在线前置会下载到内存并校验哈希，读取实际 JAR 元数据，继续补齐必需的间接前置；共享前置复用，循环引用不会无限展开。可选前置按界面开关处理。
- 依赖链中的版本冲突、下载失败、元数据缺失或超过检查上限都会阻止生成整合包，可点「重新检查依赖链」重试。预览会列出新增的间接前置及其来源。
- 依赖检查针对当前选择的版本展开，不会自动回退用户选中的直接版本来搜索其他组合。原包在线文件先做平台快速检查，未读取的 JAR 内部信息仍列为待确认。

- 每次改变选中版本、排除项和加入的前置后，按最终方案重新检查；导出前阻止明确的缺失前置、版本不符和声明冲突。多个模组的前置要求必须同时满足，界面会列出各自来源。
- 未知版本、未展开的在线文件和尚未完成检查的内部依赖会列为待确认；导出期间改变选择、环境或检查依据时需重新生成。

- 重新导出 `.mrpack` 时保留原包的在线文件描述、哈希、下载地址与环境信息；支持只有在线清单的包。
- 导出离线 zip 时会下载原包在线文件并校验内容；下载失败、源文件读不到或回读校验失败时停止导出。
- 各平台在线清单不能直接互换。无法转换时会提示使用原包格式或下载清单，避免静默丢失模组。
- 找不到满足依赖区间的版本时明确报未匹配，不再自动回退到不兼容版本。
- 模组解析支持 `META-INF/neoforge.mods.toml` 与 NeoForge 必选/可选依赖字段。

## 目录

```
index.html            页面入口，按顺序加载所有脚本
js/core/              纯逻辑：zip 读写、模组解析、分析、版本语义、识别
js/api/               Modrinth / CurseForge / 爱发电 / 图标缓存
js/pack/              三种整合包与下载清单的生成、回读校验
js/ui/                视图、事件绑定、流程
server.js             本地后端：静态服务 + 链接库 + 映射表 + 代理
data/                 运行期数据（不进 git）：缓存、映射表、中文名库
tests/                node --test 测试
```

## 已知边界

- 方块 ID / 配方冲突这类语义冲突，从模组元数据看不出来，工具不会假装能查
- 只识别公开在 Modrinth / CurseForge 的项目；纯站外发布且无映射的模组会标「未识别」
- 打包校验只保证“包结构和内容对得上”，不保证整合包在游戏里一定能启动
